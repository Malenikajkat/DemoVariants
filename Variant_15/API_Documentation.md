## 2. Эндпоинты

### 2.1. Получение списка заметок

| Параметр | Значение |
|----------|----------|
| **Название метода** | `GET /api/notes` |
| **Параметры** | Нет обязательных параметров |
| **Описание метода** | Возвращает все заметки из таблицы `notes` в формате JSON. Каждая заметка содержит: `id` — идентификатор, `title_user` — заголовок с логином пользователя (формат: `"{title} - {login}"`), `content` — содержание заметки, `formatted_date` — дата создания в формате `ДД.ММ.ГГГГ`. |
| **Формат ответа** | JSON-массив объектов |

#### Пример ответа (200 OK):

```json
[
    {
        "id": 1,
        "title_user": "Конференция ИТ - user25",
        "content": "Не забыть подготовить презентацию по проекту стоматологии к конференции 20.03.2027.",
        "formatted_date": "15.03.2027"
    },
    {
        "id": 2,
        "title_user": "Проверка оборудования - user26",
        "content": "Заказать новые стоматологические кресла для кабинета №3.",
        "formatted_date": "16.03.2027"
    },
    {
        "id": 3,
        "title_user": "Отчёт за квартал - user25",
        "content": "Подготовить отчёт по количеству пациентов за Q1 2027.",
        "formatted_date": "17.03.2027"
    }
]
```

#### Пример пустого ответа (200 OK):

```json
[]
```

#### Пример ответа (200 OK):

## 3. Коды ответов HTTP

| Код | Описание |
|-----|----------|
| **200 OK** | Запрос выполнен успешно. Возвращается список заметок (массив JSON). Если заметок нет — возвращается пустой массив `[]`. |
| **400 Bad Request** | Некорректный запрос (например, передан неверный параметр). Сервер не может обработать запрос из-за ошибки клиента. |
| **500 Internal Server Error** | Внутренняя ошибка сервера. Возникает при сбое подключения к базе данных или другой необработанной ошибке. Тело ответа содержит: `{"error": "Ошибка подключения к базе данных", "details": "описание"}` |

## 4. Структура таблицы `notes` в базе данных

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | SERIAL | Первичный ключ, автоинкремент |
| `title` | VARCHAR(255) | Заголовок заметки |
| `content` | TEXT | Содержание заметки |
| `id_user` | INTEGER | Внешний ключ к таблице `users` |
| `created_at` | TIMESTAMP | Дата и время создания |

---

## 5. Структура ответа API

| Поле ответа | Откуда и как формируется |
|-------------|--------------------------|
| `id` | Из поля `id` таблицы `notes` |
| `title_user` | Конкатенация: `"{title} - {login}"`, где `login` берётся из таблицы `users` |
| `content` | Из поля `content` таблицы `notes` (без изменений) |
| `formatted_date` | Преобразованное `created_at` в формат `ДД.ММ.ГГГГ` (например: `"15.03.2027"`) |

## 6. Как запустить API

```bash
# 1. Установить зависимости
pip install fastapi uvicorn psycopg2-binary

# 2. Создать таблицу notes
psql -U postgres -d stomatologiya -f api/001_create_notes_table.sql

# 3. Запустить сервер
python src/api_server.py

# 4. Открыть браузер
# Документация: http://127.0.0.1:8000/docs
# API: http://127.0.0.1:8000/api/notes
```

## 7. Тестирование API

### Способ 1: Через браузер
Откройте `http://127.0.0.1:8000/docs` — интерактивная документация Swagger UI.

### Способ 2: Через Postman
Импортируйте файл `tests/api_collection.postman_collection.json` в Postman и запустите коллекцию.

### Способ 3: Через curl
```bash
# Проверка работоспособности
curl http://127.0.0.1:8000/

# Получение заметок
curl http://127.0.0.1:8000/api/notes
```

### Способ 4: Через Newman (командная строка)
```bash
# Установка Newman
npm install -g newman

# Запуск тестов
newman run tests/api_collection.postman_collection.json
```

## 8. Обработка ошибок

### Ситуация: База данных не доступна
```json
{
    "error": "Ошибка подключения к базе данных",
    "details": "connection to server at \"127.0.0.1\", port 5432 failed: Connection refused"
}
```

### Ситуация: Таблица не найдена
```json
{
    "error": "Ошибка структуры базы данных",
    "details": "relation \"notes\" does not exist"
}
```

### Ситуация: Заметок нет
```json
[]
```
Это **не ошибка** — корректный ответ с пустым массивом.
