### 3.2. Задание 2. Разработка базы данных (30 мин, макс. 17 баллов)

#### 3.2.1. Цель

Оценка умения создавать базу данных на основе спроектированной ER-диаграммы, настраивать ограничения целостности и импортировать данные.

#### 3.2.2. Требования к выполнению

**Создание базы данных:**

1. Использовать **PostgreSQL** как основную СУБД.
2. Создать таблицы основных сущностей на основе ER-диаграммы (Задание 1).
3. Определить атрибуты таблиц с указанием типов данных.
4. Установить отношения между таблицами.
5. Настроить необходимые ограничения:

| Ограничение | Назначение | Пример |
|------------|-----------|--------|
| `PRIMARY KEY` | Первичные ключи | `id SERIAL PRIMARY KEY` |
| `FOREIGN KEY` | Внешние ключи со ссылочной целостностью | `ON DELETE CASCADE / ON UPDATE CASCADE` |
| `NOT NULL` | Обязательные поля | `name VARCHAR(100) NOT NULL` |
| `UNIQUE` | Уникальность значений | `login VARCHAR(50) UNIQUE` |
| `CHECK` | Проверки допустимых значений | `CHECK (quantity > 0)` |
| `DEFAULT` | Значения по умолчанию | `created_at TIMESTAMP DEFAULT NOW()` |

**Пример создания таблицы:**

```sql
CREATE TABLE customer (
    id SERIAL PRIMARY KEY,
    name VARCHAR(200) NOT NULL,
    inn VARCHAR(20) UNIQUE,
    address VARCHAR(300),
    phone VARCHAR(20),
    customer_type VARCHAR(50) NOT NULL
);
```

**Импорт данных:**

1. Импортировать данные из файла `Заказчики.json` в соответствующую таблицу БД.
2. Структура JSON-объекта:

```json

  "inn": "",
  "addres": "г. Пятигорск",
  "phone": "+79198634592",
  "type": "Поставщик"
}
```

3. Обеспечить корректность импортированных данных.

### 3.3. Задание 3. Создание запроса (20 мин, макс. 11 баллов)

#### 3.3.1. Цель

Оценка умения выполнять запросы на выборку и обработку данных на языке SQL.

#### 3.3.2. Требования к выполнению

Создать SQL-запрос, позволяющий вычислить **полную стоимость заказа покупателя** с учётом:

1. Количества продукции в заказе;
2. Стоимости всех материалов и технологических операций, использованных для производства данной продукции (с учётом нормы расхода).

**Формула расчёта:**

```
Полная_стоимость = Σ(Количество_продукции × 
    (Σ(Норма_расхода_материала × Цена_материала) + 
     Σ(Норма_времени_операции × Стоимость_операции)))
```

**Требования к запросу:**

1. Использовать объединение (JOIN) таблиц: `CustomerOrder`, `Product`, `Specification`, `Material`, `TechOperation`, `Price`.
2. Корректно обрабатывать заказы, содержащие несколько позиций продукции.
3. Результат должен содержать:

| Поле результата | Описание |
|----------------|---------|
| order_id | Идентификатор заказа |
| product_name | Наименование продукции |
| quantity | Количество |
| material_cost | Расчётная стоимость материалов |
| operation_cost | Расчётная стоимость технологических операций |
| line_total | Итоговая стоимость позиции |
| order_total | Общая сумма заказа |

4. Запрос должен быть оптимизирован и содержать комментарии.

### 3.5. Задание 5. Интеграция программных модулей (60 мин, макс. 25 баллов)

#### 3.5.1. Цель

Оценка умения выполнять интеграцию модулей в программное обеспечение, организовывать заданную интеграцию на базе имеющейся архитектуры, отлаживать программные модули и разрабатывать тестовые наборы.

#### 3.5.2. Требования к разработке API

##### 3.5.2.1. Структура таблицы базы данных `notes` (Заметки)

```sql
CREATE TABLE notes (
    id SERIAL PRIMARY KEY,
    title VARCHAR(200) NOT NULL,
    content TEXT,
    id_user INTEGER REFERENCES users(id),
    created_at TIMESTAMP DEFAULT NOW()
);
```

> Добавить в таблицу не менее **3–5 тестовых записей**.

##### 3.5.2.2. Эндпоинт API

| Параметр | Значение |
|----------|---------|
| Метод | `GET` |
| Путь | `/notes` или `/api/notes` |

##### 3.5.2.3. Правила обработки данных

Каждая заметка преобразуется в JSON-объект:

| Поле ответа | Источник и формат |
|-------------|------------------|
| `id` | Из поля `id` таблицы `notes` |
| `title_user` | Конкатенация: `"{title} - {login}"`, где `title` — из `notes`, `login` — из таблицы `users`. Пример: `"Конференция ИТ - user25"` |
| `content` | Из поля `content` таблицы `notes` (без изменений) |
| `formatted_date` | Преобразование `created_at` в формат `ДД.ММ.ГГГГ`. Пример: `"15.03.2027"` |

**Пример ответа:**

```json
[
  {
    "id": 1,
    "title_user": "Конференция ИТ - admin",
    "content": "Встреча по проекту",
    "formatted_date": "15.03.2027"
  }
]
```

##### 3.5.2.4. Обработка ошибок и HTTP-статусы

| Ситуация | HTTP-статус | Тело ответа |
|----------|------------|-------------|
| Некорректный запрос (неверный параметр, неправильный тип данных) | `400 Bad Request` | `{"error": "Сообщение об ошибке клиента"}` |
| Данные не найдены (таблица пуста / нет заметок) | `200 OK` | `[]` |
| Внутренняя ошибка сервера (сбой подключения к БД, необработанное исключение) | `500 Internal Server Error` | `{"error": "Ошибка подключения к базе данных"}` |

##### 3.5.2.5. Тестовая коллекция

В коллекцию необходимо включить следующие тесты:

| № | Тест | Описание |
|---|------|---------|
| 1 | Статус 200 | Проверка штатной работы сервера |
| 2 | Статус 500 | Проверка корректного возврата кода внутренней ошибки |
| 3 | Валидность JSON | Проверка, что сервер всегда возвращает данные в формате JSON |
